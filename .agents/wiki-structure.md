# 프로젝트 위키 구조

- 위키 경로: `./wiki` (`.agents/wiki-path`가 경로의 정본)
- 형식: OKF v0.1 스타일 Markdown + YAML frontmatter
- 언어: 현재 fork의 문서는 한국어. 코드 식별자·명령·원문 인용은 원형 유지
- 색인: 모든 위키 디렉터리에 `index.md`. 자기 범위와 바로 아래 문서·하위 색인만 연결
- 변경 이력: `wiki/logs/YYYY-MM-DD-kebab-case.md`, `logs/index.md` 최신순

## 분류 지도

- `concepts/`: 코드와 증거로 확인한 현재 제품·도메인·시스템
- `decisions/`: 사용자 또는 기존 결정 근거가 있는 번호 ADR (`0001-...md`)
- `guides/`: 개발·사용·배포·검증 절차
- `references/`: upstream·외부 조사·과거 기록·검증 증거의 출처와 탐색
- `logs/`: 위키 자체의 생성·구조·지식 변경 이력. 실행 로그·테스트 증거 저장소가 아님

## 운영 규칙

1. 새 지식은 `$wiki-update`, 탐색은 `$wiki-read`, 구조 변경은 `$wiki-setup`을 사용한다.
2. 한 문서에 한 주제. 새 문서·디렉터리는 부모 `index.md`에 등록한다. 새 분류를 미리 늘리지 않는다.
3. 현재 사실에는 확인일·코드/증거 출처를 둔다. 계획·기존 조사·지원 가능성을 구현·배포·실사용 검증 사실과 구분한다.
4. 현재 fork 지식은 위키에 갱신한다. 이관 전 일반 안내 원문은 역사 출처로 남기며 중복 갱신하지 않는다.
5. `docs/engineering/`의 기계 계약, `docs/fixes/` 원인 계약, `docs/GLOSSARY.md`의 검사 입력, 검증 산출물·승인 시안은 원래 소유 경로에 둔다. 위키는 요약과 링크만 제공한다.
6. 기존 색인과 원문은 보존한다. 오래된 계획 상태/emoji를 현재 fork의 TODO로 해석하지 않는다. 역사 문서의 주장과 현 코드가 다르면 현 코드를 확인하고 차이를 명시한다.
7. 외부 자료·과거 기록의 원문 언어·출처·승인·실패 이력은 보존한다. 증거 파일은 위키 전환을 이유로 수정하거나 삭제하지 않는다.
8. `pnpm run check:docs-index`는 기존 문서 색인과 설정된 위키의 디렉터리별 색인을 함께 확인한다. `pnpm run check:agents-sync`는 생성 AGENTS 정합성을 확인한다.
