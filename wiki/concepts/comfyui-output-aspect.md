# ComfyUI 생성물의 화면 비율

## 증상

2026-10-20 개인용 웹의 "마인크래프트 VLOG"(캔버스 비율 16:9, 내보내기 1080p)를 내보내자 모든 컷이 1920x1080 무대 한가운데에 정사각형으로 놓이고 좌우가 흰색이었다. 12초 지점 프레임의 왼쪽 위 픽셀이 순백(255,255,255)이었다.

- 프로젝트의 생성 이미지 24개는 1024x1024, Wan2.2 영상 18개는 640x640이었다. 소재가 정사각형이어서 흰 여백이 생겼다.
- 흰 무대 자체는 설계다. [내보내기 필터 그래프](../../electron/export/ffmpegFiltergraph.ts)는 미리보기 무대와 같은 흰 바탕에서 contain은 여백을 남기고 cover는 채운다고 적고 있으며 2026-06부터 원본에 있다. 그래서 내보내기 배경이나 크롭이 아니라 소재 크기에서 고친다.

## 원인

- **직접 원인:** 등록된 ComfyUI 워크플로의 출력 크기는 `comfy_width`/`comfy_height` 컨트롤로만 정해지고, 작성자가 기본값을 정사각형으로 뒀다. 캔버스·분할·Agent가 주는 `aspect_ratio`는 이 연결에서 받는 곳이 없었다.
- **구조적 원인:** 비율을 픽셀로 바꾸는 변환이 각 공급자의 `paramMap`에만 있고, 사용자가 등록한 ComfyUI 워크플로에는 그 변환도 비율 컨트롤도 없었다.
- Flux2 Klein 참조 편집은 크기를 참조 이미지에서 가져오므로 이번 원인이 아니다. 원본의 비율 반영 커밋 `0d18c1779`는 포크에 없다.

## PR #41과 한계 (병합·배포 2026-10-20, 효과 없음)

PR #41은 `electron/catalog/comfyAspectSize.ts`와 `comfyAspectApply.ts`, `aspect_ratio` 컨트롤(기본 `auto`)을 추가하고 `runTask`에서 기본값을 합치기 직전에 비율을 픽셀로 바꾸게 했다. 게이트와 단위 테스트(20개)는 통과했지만 실제 앱에서는 동작하지 않았다.

- 같은 날 배포 빌드에서 Qwen을 다시 저장해 컨트롤을 띄운 뒤 두 장을 만들었다. 비율 "자동"과 "16:9" 모두 1024x1024였다(`ffprobe` 측정). 노드 팝오버는 16:9를 골라도 가로·세로를 1024로 보여 줬다.
- 추정 원인 A(코드로 부분 확인, 실제 요청은 미확인): 캔버스 노드가 컨트롤 기본값(1024, 1024)을 요청에 채워 보내고, 결정 함수는 가로·세로가 둘 다 있으면 바로 끝낸다. 기본값과 사용자가 직접 넣은 값을 구분하지 못한다.
- 추정 원인 B: "자동"은 워크플로 기본 크기 유지라서 16:9 프로젝트에서도 정사각형이 나온다. 프로젝트 비율을 기본값으로 따르는 연결이 없다.
- 새로 가져온 MiniMax H3 두 워크플로에는 화면 비율 컨트롤이 붙지 않았다. 가로 480, 세로 864, 길이 124, 프레임레이트 24는 노출됐다.

## 진행 상황

후속 수정은 PR #42로 푸시됐고 병합·배포 전이다(2026-10-20). 단위·통합 테스트는 통과했지만 실제 앱·ComfyUI에서 픽셀 크기는 확인하지 못했다. 우선순위는 사용자가 바꾼 픽셀(컨트롤 기본값과 다른 값) > 명시한 비율 > 영상의 입력 이미지 비율 > 프로젝트 비율(렌더러가 `projectAspectRatio`로 전달) > 워크플로 기본 크기다. 에이전트·MCP의 `nomi_generate` 같은 프로젝트 정보가 없는 경로는 명시한 비율을 주지 않으면 여전히 워크플로 기본 크기를 따른다. 해당 컨트롤이 있는 ComfyUI 모델은 노드 팝오버에서 가로·세로 입력란을 숨긴다. 이 문서는 수정이 배포돼 실제 앱에서 16:9 크기로 저장되는 것을 확인한 뒤 갱신한다. 그 전까지 기존 프로젝트의 정사각형 소재는 다시 생성해야 비율이 바뀐다.
