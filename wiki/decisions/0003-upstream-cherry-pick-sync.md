# ADR 0003: 업스트림은 체리픽 장부로 따라가고 0.24 정식 릴리스 때 일괄 따라잡는다

- 상태: 채택
- 결정일: 2026-10-20

## 맥락

fork는 업스트림(aqm857886159/Nomi)에서 2026-10-08(`66d6eafed`, 0.23.1 계열)에 갈라졌다. 2026-10-20 비교에서 업스트림에만 2371개, fork에만 135개 커밋이 있었고, 시험 병합은 충돌 파일 1720개를 냈다. 업스트림 `main`은 0.24 개발 중이고 안정판은 `release/0.23.2`다. 포크 고유 작업은 문서를 뺀 코드 기준 파일 약 810개(+21,086/-3,264줄)이고, 웹 호스트·한국어 번역이 대부분 새 파일이다. 원본 파일을 고친 파일 중 업스트림도 바꾼 것은 209개다.

CLAUDE.md는 force-push, `reset`, 커밋 합치기를 금지하므로 리베이스는 쓸 수 없다.

## 결정

사용자가 이 추천 기준으로 진행하기로 했다.

1. 0.24가 정식 릴리스되기 전까지는 버그 수정만 `git cherry-pick -x`로 골라 가져온다. 업스트림이 0.23.x에 따로 옮긴 "0.23.x 이식" 커밋을 우선한다.
2. 검토한 모든 커밋을 [업스트림 동기화 장부](../../docs/upstream-sync.md)에 채택·제외(사유)로 기록한다. 마지막 검토 지점은 `08597facd`(2026-10-19)이고, 다음에는 `git log <SHA>..upstream/main`과 `git cherry -v`로 새 것만 본다.
3. 업스트림에 `v0.24.0` 태그가 생기면 그 태그에서 새 브랜치를 만들어 fork 고유 작업을 다시 얹고, `merge -s ours`로 기존 이력을 병합 기록한 뒤 `main`을 빨리감기한다. 이후에는 업스트림 릴리스마다 병합한다.
4. fork 고유 변경은 가능하면 원본 파일 밖(별도 파일)에 둔다. 로케일 표 수정처럼 원본 파일을 고친 부분이 충돌을 만든다.

## 결과

- 2026-10-20 체리픽 PR 3건을 병합했다: #38(Agent·지출 안정성), #39(MCP 확인 카드), #40(산출물 바이트 타입 검사).
- 건너뛴 것: MCP HTTP 서버·데스크톱 포워더(0.24 신규, fork 배포는 웹 호스트), 분할 표 읽기(업스트림 PR #1252의 노드가 병합 전), 텔레메트리, 3D-BOX 감독 화면 통합.
- 비용: 의존이 깊은 수정은 체리픽이 어렵다. 이식판에서도 포크가 이식 범위에 없는 동작(예: `draft_shots`의 `null`)은 그대로 거부된다.
- 위험: 0.24 정식 릴리스가 늦어지면 후보가 쌓인다. 일정은 확인하지 못했다. 후보가 일정 수준 이상 쌓이면 이 결정을 다시 본다.
- 업스트림에 넘길 만한 수정(예: [ComfyUI 등록 삭제 사고](../concepts/comfyui-workflow-registration.md)의 원인)은 별도로 검토한다.
