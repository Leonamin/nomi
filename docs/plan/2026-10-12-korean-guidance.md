## 설계 카드

분류: 기타 — 기존 화면의 언어 추가. 새 제품 화면·생성·결제 동작은 추가하지 않는다.

| 항목 | 결정과 확인 방법 |
|---|---|
| ★1 사용자 | 일반 학생이 처음 방문해 프로젝트를 만들고, 장면을 설명하고, 연결된 ComfyUI 모델로 생성한 뒤 타임라인에 배치하고 MP4로 저장한다. 실제 과제: 학교 소개 장면, 발표용 짧은 영상. 실제 생성·내보내기는 자원 확보 후 확인하며 현재 unverified. |
| ★2 소유권 | 화면 문구는 `src/i18n/`, 서버 문구는 `electron/desktopStrings.ts`, 언어 상태는 기존 i18n과 `desktopLocale.ts`가 소유한다. `node scripts/door-map.mjs src/i18n/index.ts`: 읽기 13, 쓰기 3 경로. 프로젝트 데이터 형식은 바꾸지 않는다. |

| ★4 상태 | 빈 화면은 첫 행동을 알려준다. 로딩은 진행 중인 일을 말한다. 완료는 결과 위치를 알려준다. 실패는 이유와 다음 행동을 말한다. 부분 성공·취소 중·만료도 기존 의미를 보존하며, 서버 오류 코드·모델 ID·사용자 입력은 번역하지 않는다. |

## 현재 다국어 구조

기준: `origin/main`의 `3f5ba5e728b4123a4d18d470129ff31db0eae985`.

- `src/i18n/index.ts`: `SUPPORTED_LOCALES = ['zh-CN', 'en']`. 선택은 `nomi:locale:v1`에 저장하며 문서 lang와 서버/데스크톱으로 전달한다. 기본값과 누락 번역 fallback은 중국어다.
- `src/i18n/resources.ts`: 기능별 TypeScript 사전을 조합한다. 영어 사전 문자열은 6,047개다. 영어는 중국어와 같은 구조를 갖는 `TranslationShape` 검사를 받는다.
- `src/workbench/settings/SettingsDialog.tsx`: 지원 언어 목록으로 버튼을 만들지만 표시 이름 표도 별도로 추가해야 한다.
- `src/desktop/bridge.ts`, `electron/desktopLocale.ts`, `electron/settings/portableConfig.ts`: 언어 타입/설정 스키마가 두 언어로 제한되어 있다. 한국어를 함께 연결해야 한다.
- `electron/desktopStrings.ts`: 서버/데스크톱 문구의 별도 사전이다. UI 사전만 추가하면 서버 오류는 한국어가 되지 않는다.
- `web/client.ts`: 브라우저 언어를 초기 언어 탐지에 사용한다. `web/rpc.ts`의 언어 변경은 서버 전역 `setDesktopLocale`에 전달된다. 이 웹은 개인용 단일 사용자이며 다중 사용자 언어 격리를 제공하지 않는다.
- `src/workbench/onboarding/handbookContent.ts`: 설명서는 i18next 밖에 있으며 `locale !== 'en'`이면 중국어를 반환한다. 한국어 문서 소스를 별도로 연결해야 한다.
- `src/i18n/modelDisplayText.ts`: 영어일 때만 모델 설명을 치환한다. 모델·프롬프트·스킬 라이브러리와 예제 프로젝트에도 별도 언어 분기가 있으므로 점검 대상이다.
- `scripts/check-i18n-key-parity.ts`: 현재 중국어/영어 키와 영어 내 한자만 검사한다. 한국어 키 누락·보간값 불일치도 검증 대상으로 확장해야 한다.
- 앱이 표시한 사용자 원문, 외부 모델이 제공한 이름과 자료, 운영체제 대화상자는 앱 번역 범위와 구분한다. 한국어 UI를 추가한다고 모든 외부 콘텐츠가 번역되지는 않는다.

한국어 추가에 라이브러리 교체는 필요 없다. 다만 지원 목록에 `ko` 하나를 추가하는 것만으로는 완성되지 않는다.

## 한국어 작성 기준

Sepia `write` 사용. 일반 학생을 독자로 삼고, 기능의 실제 동작을 근거로 새 한국어 문구를 작성한다. 전문 문서·스타일·튜토리얼 지침을 읽었다. Executor: GPT-6, 상세 버전 미확정; GPT 문체 표는 prior로 적용. 한국어 사용자 안내의 기존 표본은 없어 학생용 안내를 기준으로 삼는다.

- 짧은 버튼은 행동을 쓴다: 만들기, 저장, 다시 시도.
- 처음 쓰는 설명은 결과를 먼저 말한다: “만들고 싶은 장면을 적어 주세요.”
- node는 학생에게 보이는 문맥에서 “카드”, prompt는 “장면 설명”으로 풀되, 실제 코드나 기술 설정의 정확한 이름은 유지한다.
- “모델”은 처음에 “이미지나 영상을 만드는 AI”로 설명한다. ComfyUI, API, ID 등 필요한 고유명칭을 억지로 바꾸지 않는다.
- 삭제·취소·비용·업로드의 조건은 짧게 쓰더라도 빠뜨리지 않는다.
- 개인 웹에서 지원하지 않는 AI Agent 자동 제작·TTS·결제 등을 가능한 일로 안내하지 않는다. 영어·중국어 원문은 유지한다.

## 샘플과 현재 확인

- [체험 샘플](../design/mockups/2026-10-12-korean-guidance/index.html): 프로젝트 시작, 언어 설정, 학생용 도움말. 실제 UI를 확인한 뒤 기존 배치와 토큰으로 작성한 문구 검토용 샘플이며 실제 생성 버튼이 아니다.
- [학생용 한국어 안내 초안](../user-guide.ko.md).
- `pnpm install`, `pnpm run delivery:preflight`, 기존 코드의 `pnpm run build:web` 성공. build의 기존 chunk/import.meta 경고는 남아 있다.
- 격리된 로컬 웹 `9132`와 별도 임시 데이터로 영어 프로젝트·설정 화면 확인. 운영 데이터와 공유 작업 디렉터리는 변경하지 않았다.
- 사용자 샘플 승인과 번역 에이전트 3개 사용 승인을 받았다. 전체 한국어 문구와 연결을 구현하고 검증 중이며, 운영 배포는 하지 않는다.

## 구현과 검증 결과

- 승인한 학생용 말투로 UI 6,048개 키를 추가했다. 앱 설정·언어 저장·OS 탐지·웹/데스크톱 안내·예제·서버 오류 문구를 연결했다.
- 지원 언어와 정규화는 `electron/shared/contracts/locale.ts`가 소유한다. 렌더러와 호스트가 이 계약을 사용하며 호스트 언어 상태는 `desktopLocale.ts`에 유지한다.
- 기존 영어·중국어 UI 값을 최초 원본과 깊은 비교하여 동일함을 확인했다. 두 사전에는 한국어 선택 버튼 이름만 추가했다.
- [검증 기록](../qa/2026-10-12-korean-guidance.md): 실제 ko/en/zh 화면과 언어 왕복·새로고침, 타입·키·빌드·테스트 결과 및 미검증 범위.
- [독립 검수 B](../qa/2026-10-12-korean-independent-b.md), [독립 검수 C](../qa/2026-10-12-korean-independent-c.md): 구현선과 다른 검수선에서 의미·연결을 확인하고 발견한 오류를 수정했다.
- 실제 이미지/영상 생성과 MP4 결과 검증은 연결된 생성 자원이 없어 unverified. 전체 gates의 기존 화면 기준 불일치는 원본 브랜치와 비교해 기록하며 기준을 자동 갱신하지 않는다.
