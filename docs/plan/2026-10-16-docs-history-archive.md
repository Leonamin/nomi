## 경로 원칙

- 사용자가 명시한 과거 문서 이동에 따라 역사 묶음을 `docs/archive/<기존 분류>/`로 옮긴다. 기존 색인도 이동해 보존하고 상대 링크를 맞춘다.
- 현재 작업의 새 설계 카드는 기존 지침대로 `docs/plan/`에 둘 수 있다. 과거 계획의 스캔·색인과 새 계획의 생성 위치를 구분한다.
- 원인 계약의 immutable 역사 스키마나 원본 로그·이미지·영상·실험 데이터의 내용은 경로 치환을 이유로 바꾸지 않는다. 이동이 그 기계 소비자를 깨뜨리면 해당 입력은 원래 경로에 유지한다.
- live 안내와 소스/도구 참조는 canonical 새 경로로 고친다. 과거 실행 로그 안의 원래 경로는 당시 증거로 보존한다.

## 先查别人

- 기존 [문서 색인 스캐너](../../scripts/docs-index-lib.mjs)가 링크·등록 판정의 소유자이므로 archive 루트를 여기에 추가해 재사용한다.
- 기존 [문서 상태 소유자](../../scripts/doc-status-lib.mjs)가 계획 수집의 단일 기준이므로 별도 아카이브 스캐너를 만들지 않고 원래 live 루트와 보관 루트를 함께 수집한다.
- 기존 [문서 자동 보정](../../scripts/repair-doc-gates.mjs)과 [장부 생성기](../../scripts/build-delivery-ledger.mjs)가 사용하는 정식 입력/출력 경로를 맞추며 검증 기준을 낮추지 않는다.

## 이동 중 발견한 도구 결함

- 진행 확인 hook의 기존 존재하지 않는 계획 경로를 보관 원문의 실제 위치로 고쳤다. 임시 Git 저장소 회귀 검증으로 staged 완료 행만 인정하는 기존 계약을 확인한다.
- 민감정보 검사에서 보관 복사와 원주소 안내가 기존 비공개 작업 번호를 새 값으로 오인했다. Git이 판정한 복사·이동 원문의 기존 번호만 상속하며 새 번호·전체 파일의 자격증명 검사는 유지한다. 실제 Git staged/committed 복사·이동 및 자격증명 차단 34건으로 검증한다. 변경한 현재 도구 설명에서는 불필요한 과거 작업 번호를 제거하고 보관 원문은 보존한다.
