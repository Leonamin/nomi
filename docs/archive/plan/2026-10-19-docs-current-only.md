# 현재 규범·기계 계약과 과거 자료의 분리

> 📎 상태: 구조 정리 기록 · 2026-10-19 사용자 승인 범위. 검증·병합 상태는 해당 PR에서 확인한다.

## 设计卡

| 격 | 결정 |
| --- | --- |
| ★1 사용자 작업 | docs에서는 현재 규범·기계 계약·진행 중 작업만 찾고, 과거 증거·시안·교훈은 archive 색인에서 찾는다. |
| ★2 소유권 | wiki는 현재 설명, docs/engineering과 fixes의 JSON은 기계 계약, docs/design은 현재 디자인 규범, archive는 원문과 증거. immutable v1/v2 계약은 바이트 유지하고 그 계약이 직접 고정하는 최소 입력만 예외로 남긴다. |
| ★3 재사용 | 기존 Markdown 링크 파서·문서 색인·상태·ledger·Git rename/copy provenance를 재사용한다. 이동표로 파일 참조를 한 번에 수정하며 경로 alias나 symlink를 추가하지 않는다. |
| ★4 자료 상태 | 과거 계획·시안·실패·승인 증거는 당시 의미를 유지한다. 원본 JSON·로그·이미지·영상은 바이트 보존하고 실행 스크립트의 import 및 문서 링크만 새 위치에 맞춘다. |
| ★9 검증과 복구 | 원본→목적지 manifest/해시, 제거 포인터·참조 검사, 기존 유효 링크 비교, 도구 회귀와 전체 gates로 확인. 별도 Luna 검수. 오류 시 PR revert. 제품 UI·유료 생성·배포 변경 없음. |

## 先查别人

- [기존 문서 색인](../../../scripts/docs-index-lib.mjs): 기존 문서 링크·색인 소유 경계에 보관 교훈 루트를 적용한다.
- [기존 문서 상태 수집](../../../scripts/doc-status-lib.mjs): 현재 작업과 보관 계획 수집을 기존 소유자에서 유지한다.
- [기존 ledger 생성기](../../../scripts/build-delivery-ledger.mjs): 기존 생성기와 기준 경로를 맞추고 기존 debt 기준은 증가시키지 않는다.

## 범위

과거 evidence/qa/시안/실험 패키지는 실제로 이동하고 실행 소비자의 경로를 수정한다. 옛 주소 안내는 직접 참조를 고쳐 제거하며 immutable 계약이 꼭 요구하는 최소 주소만 예외로 기록한다. 과거 계약의 업무 의미나 증거 결과는 다시 쓰지 않는다.
